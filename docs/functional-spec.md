# moov 기능 명세

유즈케이스([use-cases.md](./use-cases.md))를 화면/기능 단위로 분해한 기능 요구사항(FR)이다. 각 FR은 GitHub Issue(`[FR-XX]`)로도 등록된다.

## FR-01. 운동 세션 CRUD

- **개요**: 운동 세션을 생성/조회/수정/삭제한다.
- **상세 요구사항**:
  - 세션은 날짜, 하나 이상의 파트(각 파트는 포맷·태그가 부여된 운동 블록·결과로 구성), 컨디션 메모, 노트로 구성된다.
  - 세션 삭제 시 확인 다이얼로그를 표시한다.
- **수용 기준**:
  - Given 세션 작성 화면에서, When 필수 항목을 채우고 저장하면, Then 세션이 목록에 나타난다.
  - Given 저장된 세션이 있을 때, When 삭제를 확정하면, Then 목록에서 사라진다.
- **연관 데이터 모델**: `WorkoutSession`, `WorkoutPart`
- **연관 유즈케이스**: UC-01, UC-02

## FR-02. 운동 포맷 선택

- **개요**: 세션 내 파트(Part)마다 운동 포맷(EMOM/AMRAP/For Time/Interval/Rounds/Strength)을 선택한다.
- **상세 요구사항**:
  - 포맷은 열거형으로 관리하며 이후 결과 입력 방식(FR-04)을 결정한다.
  - 포맷별 타임캡(선택) 입력을 지원한다.
  - 한 세션에 여러 파트가 있을 수 있고, 파트마다 서로 다른 포맷을 가질 수 있다(예: Part 1은 Strength, Part 2는 For Time).
- **수용 기준**:
  - Given 파트 작성 중, When 포맷을 EMOM으로 선택하면, Then 결과 입력 UI가 EMOM에 맞게 바뀐다.
  - Given 세션에 파트가 2개 있을 때, When 각각 다른 포맷을 선택하면, Then 두 파트가 서로 다른 결과 입력 UI를 갖는다.
- **연관 데이터 모델**: `WorkoutPart.format`
- **연관 유즈케이스**: UC-01

## FR-03. 운동 블록 입력

- **개요**: 종목 단위 운동 블록을 추가/수정/삭제하고, 각 블록에 하나 이상의 태그(웜업/본운동/보조운동 등)를 부여한다.
- **상세 요구사항**:
  - 블록은 종목명, 무게, 무게 단위(lb/kg), 반복수, 세트수, 휴식시간(선택), 태그 목록을 갖는다.
  - 한 파트에 여러 블록을 순서대로 추가할 수 있으며, 블록 순서와 태그는 서로 독립적이다(태그가 곧 순서를 의미하지 않는다).
  - 블록당 태그는 기본 제공 태그(웜업/본운동/보조운동 등)와 사용자 정의 태그(FR-12)를 함께 다중 선택할 수 있다.
- **수용 기준**:
  - Given 블록 입력 화면에서, When 종목/무게/반복수를 입력하고 블록을 추가하면, Then 블록이 목록에 순서대로 표시된다.
  - Given 블록 입력 중, When "본운동"과 "컨디셔닝" 태그를 동시에 선택하면, Then 두 태그가 모두 블록에 저장된다.
- **연관 데이터 모델**: `ExerciseBlock`, `Tag`
- **연관 유즈케이스**: UC-01

## FR-04. 결과 입력

- **개요**: 파트마다 선택된 포맷에 맞는 결과 타입(시간/라운드+렙/성공-미완수/최대중량)으로 결과를 입력한다.
- **상세 요구사항**:
  - For Time/Interval → 완료 시간 또는 미완수 사유.
  - AMRAP/Rounds → 라운드 수 + 추가 렙.
  - EMOM/Strength → 성공/실패 또는 최대 중량.
  - 결과가 없는 파트(예: 웜업)는 결과 입력을 생략할 수 있다.
- **수용 기준**:
  - Given AMRAP 포맷 파트에서, When 결과를 "3라운드 + 12reps"로 입력하면, Then 해당 파트 상세에 결과가 표시된다.
- **연관 데이터 모델**: `WorkoutResult`
- **연관 유즈케이스**: UC-01

## FR-05. 세션 목록/상세 뷰

- **개요**: 기록된 세션을 날짜 역순 목록으로 보여주고, 선택 시 상세 화면으로 이동한다.
- **상세 요구사항**:
  - 목록 항목에는 날짜와 파트별 포맷·결과 요약이 표시된다.
  - 상세 화면에는 파트별로 포맷과 태그로 구분된 운동 블록 목록·결과, 그리고 세션 노트 전체가 표시된다.
- **수용 기준**:
  - Given 세션이 여러 개 있을 때, When 목록 화면에 진입하면, Then 최신 날짜 순으로 정렬되어 표시된다.
- **연관 데이터 모델**: `WorkoutSession`
- **연관 유즈케이스**: UC-02

## FR-06. 종목별 히스토리 뷰

- **개요**: 특정 종목을 선택하면 해당 종목이 등장한 모든 기록을 시간순으로 조회한다.
- **상세 요구사항**:
  - 무게/반복수 변화를 리스트 또는 그래프로 표시한다.
  - 종목명으로 검색/필터링할 수 있다.
  - 종목 매칭은 자유 텍스트가 아니라 종목 카탈로그(FR-11)의 `Exercise` 참조를 기준으로 하여, 표기 차이(대소문자, 띄어쓰기 등)로 인한 기록 누락을 방지한다.
- **수용 기준**:
  - Given "Back Squat"을 3회 기록했을 때, When 히스토리 화면에서 검색하면, Then 3건이 시간순으로 표시된다.
- **연관 데이터 모델**: `ExerciseBlock`, `Exercise`
- **연관 유즈케이스**: UC-03

## FR-07. PR(1RM) 등록/갱신

- **개요**: 종목별 개인 기록(1RM)을 등록하고 갱신 이력을 보존한다.
- **상세 요구사항**:
  - 신규 PR 등록 시 기존 값과 비교해 갱신 여부를 표시한다.
  - 과거 PR 이력을 모두 보존해 추이를 조회할 수 있다.
- **수용 기준**:
  - Given 기존 Back Squat PR이 265lb일 때, When 275lb로 등록하면, Then 갱신으로 표시되고 이전 값도 이력에 남는다.
- **연관 데이터 모델**: `PersonalRecord`
- **연관 유즈케이스**: UC-04

## FR-08. 컨디션 노트 입력

- **개요**: 세션에 통증 부위/강도 및 자유 텍스트 메모를 남긴다.
- **상세 요구사항**:
  - 통증 부위와 강도(1~10)는 선택 입력이다.
  - 자유 텍스트 메모만 단독으로도 저장 가능하다.
- **수용 기준**:
  - Given 세션 작성 중, When 통증 강도 없이 메모만 입력하고 저장하면, Then 정상 저장된다.
- **연관 데이터 모델**: `ConditionNote`
- **연관 유즈케이스**: UC-05

## FR-09. 운동 프로그램 템플릿 CRUD

- **개요**: 반복 사용할 운동 구성을 템플릿으로 저장하고 세션에 적용한다.
- **상세 요구사항**:
  - 템플릿은 파트(포맷 포함)와 태그가 부여된 운동 블록 구성을 포함한다.
  - 세션 작성 시 템플릿을 불러오면 파트와 블록이 자동으로 채워지고, 이후 자유롭게 수정 가능하다.
  - 템플릿 삭제는 이미 생성된 세션에 영향을 주지 않는다.
- **수용 기준**:
  - Given 저장된 템플릿이 있을 때, When 새 세션에서 템플릿을 불러오면, Then 파트와 태그가 부여된 운동 블록이 자동으로 채워진다.
- **연관 데이터 모델**: `WorkoutTemplate`, `TemplatePart`, `TemplateBlock`
- **연관 유즈케이스**: UC-06

## FR-10. 운동 블록 태그 부여

- **개요**: 운동 블록마다 하나 이상의 태그(웜업/본운동/보조운동 등)를 부여해 구간을 구분한다.
- **상세 요구사항**:
  - 태그는 블록당 다중 선택 가능하며, 블록 순서와 태그는 서로 독립적이다.
  - 기본 제공 태그(웜업/본운동/보조운동)와 사용자 정의 태그(FR-12)를 함께 선택할 수 있다.
- **수용 기준**:
  - Given 블록 입력 화면에서, When "본운동"과 "컨디셔닝" 태그를 동시에 선택하면, Then 두 태그가 모두 블록에 저장된다.
- **연관 데이터 모델**: `ExerciseBlock.tags`, `Tag`
- **연관 유즈케이스**: UC-01

## FR-11. 사용자 정의 운동 종목 관리

- **개요**: 프리셋에 없는 운동 종목을 사용자가 직접 추가/수정/삭제할 수 있다.
- **상세 요구사항**:
  - 종목은 이름, 카테고리(선택), 기본 무게 단위(선택)로 구성된 카탈로그 항목이다.
  - 블록 입력 시 카탈로그에서 검색/선택하거나 새 종목을 즉시 추가할 수 있다.
  - 종목을 삭제하면 참조만 끊어지고, 이미 기록된 블록/PR에는 삭제 시점까지 저장된 종목명 스냅샷이 남아 과거 기록의 종목명이 유지된다(과거 기록 불변).
  - 이미 기록에 사용 중인 종목을 삭제하려 할 때, "이미 N개 기록에 사용 중입니다. 삭제해도 과거 기록의 종목명은 유지됩니다" 형태의 확인 다이얼로그를 표시한다.
- **수용 기준**:
  - Given 카탈로그에 없는 "Sandbag Carry"를 블록 입력 중 새로 추가하면, Then 카탈로그에 저장되고 이후 블록 입력 시 선택 목록에 나타난다.
  - Given "Back Squat"이 이미 여러 블록에 사용 중일 때, When 카탈로그에서 삭제를 시도하면, Then 사용 중 안내가 담긴 확인 다이얼로그가 표시되고, 삭제를 확정해도 기존 블록의 종목명 표시는 바뀌지 않는다.
- **연관 데이터 모델**: `Exercise`, `ExerciseBlock.exerciseName`
- **연관 유즈케이스**: UC-01, UC-07

## FR-12. 사용자 정의 태그 관리

- **개요**: 프리셋 태그로 충분하지 않을 때 사용자가 새 태그를 추가/수정/삭제할 수 있다.
- **상세 요구사항**:
  - 태그는 이름과 색상(선택)으로 구성된다.
  - 이미 블록에 사용 중인 태그를 삭제하면 해당 블록에서 태그만 제거되고 블록/기록은 유지된다.
- **수용 기준**:
  - Given 태그 관리 화면에서, When "스킬"이라는 새 태그를 추가하면, Then 블록 태그 선택 목록에 "스킬"이 나타난다.
- **연관 데이터 모델**: `Tag`
- **연관 유즈케이스**: UC-01, UC-08

## FR-13. 태그별 집계 추이 조회

- **개요**: 특정 태그가 부여된 모든 운동 블록을 기간별로 집계해 볼륨/빈도 추이를 보여준다.
- **상세 요구사항**:
  - 집계 단위는 주/월 등 기간별 볼륨(세트×렙 등) 또는 세션/블록 빈도.
  - 기본 제공 태그와 사용자 정의 태그(FR-12) 모두 집계 대상이 된다.
- **수용 기준**:
  - Given "Conditioning" 태그가 부여된 블록이 여러 세션에 걸쳐 있을 때, When 태그별 집계 화면에서 해당 태그를 선택하면, Then 기간별 볼륨/빈도 추이가 표시된다.
- **연관 데이터 모델**: `ExerciseBlock.tags`, `Tag`
- **연관 유즈케이스**: UC-03

## FR-14. 최초 실행 온보딩

- **개요**: 앱을 처음 실행한 사용자에게 세션/히스토리/PR/관리 각 탭의 기능을 순서대로 소개한다.
- **상세 요구사항**:
  - 페이지 단위로 구성되며, "다음"/"건너뛰기" 컨트롤을 제공한다.
  - 온보딩 완료(또는 건너뛰기) 여부를 로컬에 저장해, 이후 실행 시 자동으로 다시 표시하지 않는다.
  - 관리 탭에 "온보딩 다시 보기" 진입점을 제공해 사용자가 언제든 수동으로 다시 열람할 수 있다.
- **수용 기준**:
  - Given 앱을 처음 설치해 실행했을 때, When 앱이 시작되면, Then 온보딩 화면이 자동으로 표시된다.
  - Given 온보딩 화면에서, When "건너뛰기"를 누르면, Then 온보딩이 즉시 종료되고 이후 실행 시 다시 표시되지 않는다.
  - Given 온보딩을 이미 마친 사용자가, When 관리 탭에서 "온보딩 다시 보기"를 선택하면, Then 동일한 온보딩 화면을 다시 볼 수 있다.
- **연관 데이터 모델**: 없음 (UserDefaults/AppStorage 기반 로컬 플래그, 별도 SwiftData 엔티티 불필요)
- **연관 유즈케이스**: UC-09

## FR-15. 업데이트 안내(릴리스 노트)

- **개요**: 앱이 업데이트된 후 첫 실행 시, 온보딩과 동일한 컴포넌트를 재사용해 해당 버전의 변경 사항을 안내한다.
- **상세 요구사항**:
  - 버전별 변경 사항 콘텐츠는 앱 번들 내 정적 데이터로 관리한다.
  - 마지막으로 안내를 확인한 앱 버전을 로컬에 저장해, 그보다 높은 버전으로 실행될 때만 표시한다.
  - 온보딩과 동일한 "다음"/"건너뛰기" 컨트롤을 제공하며, 관리 탭에서 지난 업데이트 노트를 다시 볼 수 있는 진입점도 제공한다.
- **수용 기준**:
  - Given 사용자가 이전 버전을 사용 중이었고, When 새 버전으로 업데이트한 후 앱을 실행하면, Then 새 버전의 변경 사항 안내가 표시된다.
  - Given 이미 해당 버전의 안내를 확인했다면, When 앱을 다시 실행해도, Then 안내가 다시 표시되지 않는다.
- **연관 데이터 모델**: 없음 (UserDefaults/AppStorage 기반 마지막 확인 버전 저장, 별도 SwiftData 엔티티 불필요)
- **연관 유즈케이스**: UC-09

## FR-16. 버전 정보 화면

- **개요**: 현재 앱의 마케팅 버전과 빌드 번호를 확인할 수 있는 화면을 제공한다.
- **상세 요구사항**:
  - Bundle의 CFBundleShortVersionString(마케팅 버전), CFBundleVersion(빌드 번호)을 표시한다.
  - 관리 탭 "도움말" 섹션에 진입점을 추가한다.
  - 필요 시 온보딩 다시 보기/업데이트 노트로 이동하는 링크를 함께 제공한다.
- **수용 기준**:
  - Given 사용자가 관리 탭에서 "버전 정보"를 선택하면, When 화면이 열리면, Then 현재 마케팅 버전과 빌드 번호가 표시된다.
- **연관 데이터 모델**: 없음 (Bundle.main.infoDictionary 기반, 별도 SwiftData 엔티티 불필요)
- **연관 유즈케이스**: UC-10

## FR-17. 데이터 내보내기 (Export)

- **개요**: 사용자의 전체 운동 기록 데이터를 파일로 내보낸다.
- **상세 요구사항**:
  - 세션/파트/블록/결과/종목/태그/PR/컨디션 메모/템플릿 전체를 이식 가능한 포맷(JSON 등)으로 직렬화한다.
  - 시스템 공유 시트(예: UIActivityViewController 계열)로 저장/전송할 수 있게 한다.
  - 관리 탭에 진입점을 제공한다.
- **수용 기준**:
  - Given 데이터가 존재하는 상태에서, When "데이터 내보내기"를 실행하면, Then 내보내기 파일이 생성되고 공유 시트가 표시된다.
- **연관 데이터 모델**: 전체 엔티티 (`WorkoutSession`, `WorkoutPart`, `ExerciseBlock`, `WorkoutResult`, `Exercise`, `Tag`, `PersonalRecord`, `ConditionNote`, `WorkoutTemplate`, `TemplatePart`, `TemplateBlock`)
- **연관 유즈케이스**: UC-11

## FR-18. 데이터 가져오기 (Import)

- **개요**: 내보내기(FR-17)로 생성된 파일을 읽어 데이터를 복원한다.
- **상세 요구사항**:
  - 파일 선택기(문서 선택기 등)로 가져올 파일을 선택한다.
  - 파일 형식/스키마 검증에 실패하면 오류를 안내하고 가져오기를 중단한다.
  - 기존 데이터가 이미 있으면 병합할지 교체할지 사용자에게 확인한다.
- **수용 기준**:
  - Given 유효한 내보내기 파일이 있을 때, When 가져오기를 실행하면, Then 데이터가 복원된다.
  - Given 형식이 올바르지 않은 파일을 선택했을 때, When 가져오기를 시도하면, Then 오류 안내가 표시되고 기존 데이터는 변경되지 않는다.
- **연관 데이터 모델**: 전체 엔티티 (`WorkoutSession`, `WorkoutPart`, `ExerciseBlock`, `WorkoutResult`, `Exercise`, `Tag`, `PersonalRecord`, `ConditionNote`, `WorkoutTemplate`, `TemplatePart`, `TemplateBlock`)
- **연관 유즈케이스**: UC-11

## FR-19. 종목/태그 검색형 선택 UI

- **개요**: 블록 편집(세션/템플릿) 및 PR 등록 화면에서 종목/태그를 토글 목록 대신, 검색어로 후보를 좁혀 선택하는 datalist 스타일 UI로 변경한다.
- **상세 요구사항**:
  - **종목 선택**: 검색어를 입력하면 이름에 검색어가 포함된 종목만 필터링해 목록으로 보여주고, 목록에서 선택한다. 일치하는 종목이 없으면 자연스럽게 "새 종목 추가"로 이어진다(FR-11).
  - **태그 선택**: 다중 선택이 가능해야 하므로, 검색으로 후보를 좁히고 선택된 태그는 칩(chip) 형태로 표시하며 목록에서 다시 선택/해제할 수 있다. 일치하는 태그가 없으면 "새 태그 추가"로 이어진다(FR-12).
  - **적용 대상 화면**: `BlockFormView`(세션 블록, FR-03/FR-10), `TemplateBlockFormView`(템플릿 블록, FR-09), `PersonalRecordFormView`(PR 등록, FR-07)의 종목 선택 UI.
  - 기존 토글 리스트(`ForEach` + `Toggle`)와 단순 Picker 방식을 대체한다.
- **수용 기준**:
  - Given 종목이 여러 개 등록되어 있을 때, When 검색창에 검색어를 입력하면, Then 이름에 검색어가 포함된 종목만 목록에 표시된다.
  - Given 태그가 여러 개 등록되어 있을 때, When 태그를 검색해 여러 개를 선택하면, Then 선택된 태그들이 칩으로 표시되고 블록에 모두 저장된다.
  - Given 검색어와 일치하는 종목/태그가 없을 때, When 목록을 확인하면, Then "새로 추가" 진입점이 자연스럽게 노출된다.
- **연관 데이터 모델**: `Exercise`, `Tag` (기존과 동일, 신규 필드 없음 — 선택 UI만 변경)
- **연관 유즈케이스**: UC-01, UC-04, UC-06, UC-07, UC-08
