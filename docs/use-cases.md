# moov 유즈케이스 명세

식단 등 운동과 무관한 항목은 범위에서 제외한다. 각 유즈케이스는 GitHub Issue(`[UC-XX]`)로도 등록된다.

## UC-01. 운동 세션 기록

- **액터**: 사용자
- **전제 조건**: 앱이 실행되어 있다.
- **트리거**: 사용자가 "새 세션 기록"을 시작한다.
- **기본 흐름**:
  1. 사용자가 세션 날짜를 입력한다.
  2. 사용자가 하나 이상의 파트(Part)를 추가하고, 파트마다 운동 포맷(EMOM/AMRAP/For Time/Interval/Rounds/Strength)을 선택한다.
  3. 사용자가 각 파트에 운동 블록(종목명, 무게, 무게 단위, 반복수, 세트수, 휴식시간)을 순서대로 추가한다.
  4. 사용자가 각 블록에 하나 이상의 태그(웜업/본운동/보조운동 등)를 부여한다. 태그 종류나 개수, 블록 순서에는 제약이 없다.
  5. 사용자가 각 파트의 포맷에 맞는 결과(시간, 라운드+렙, 성공/미완수, 최대중량 등)를 입력한다. 결과가 없는 파트(예: 웜업)는 비워둘 수 있다.
  6. 사용자가 세션을 저장한다.
- **예외 흐름**: 필수 항목(날짜, 하나 이상의 파트와 파트별 포맷)이 누락되면 저장이 차단되고 안내 메시지가 표시된다.
- **사후 조건**: 세션이 저장되어 세션 목록에 표시된다.
- **연관 기능 요구사항**: FR-01, FR-02, FR-03, FR-04, FR-10

## UC-02. 운동 세션 조회

- **액터**: 사용자
- **전제 조건**: 하나 이상의 세션이 기록되어 있다.
- **트리거**: 사용자가 세션 목록 화면에 진입한다.
- **기본 흐름**:
  1. 사용자가 세션 목록을 날짜 역순으로 확인한다.
  2. 사용자가 특정 세션을 선택한다.
  3. 앱이 해당 세션의 파트 목록(파트별 포맷, 태그로 구분된 운동 블록, 결과)과 노트를 상세 화면에 표시한다.
- **예외 흐름**: 기록된 세션이 없으면 빈 상태(empty state) 화면을 표시한다.
- **사후 조건**: 없음 (조회 전용).
- **연관 기능 요구사항**: FR-05

## UC-03. 종목별/태그별 기록 추이 조회

- **액터**: 사용자
- **전제 조건**: 동일 종목 또는 동일 태그가 둘 이상의 세션에 기록되어 있다.
- **트리거**: 사용자가 특정 종목(예: Back Squat)을 선택해 히스토리 화면에 진입하거나, 특정 태그(예: Conditioning)를 선택해 집계 화면에 진입한다.
- **기본 흐름**:
  1. (종목 기준) 앱이 해당 종목이 등장한 모든 세션의 무게/반복수를 시간순으로 조회한다. 종목 매칭은 종목 카탈로그(FR-11)의 동일 Exercise 참조를 기준으로 하여, 표기 차이로 인한 기록 누락을 방지한다.
  2. (태그 기준) 앱이 해당 태그가 부여된 모든 블록을 기간별(주/월)로 집계해 볼륨/빈도를 계산한다.
  3. 사용자가 리스트 또는 추이 그래프로 변화를 확인한다.
- **예외 흐름**: 해당 종목/태그 기록이 하나뿐이면 그래프 대신 단일 값만 표시한다.
- **사후 조건**: 없음 (조회 전용).
- **연관 기능 요구사항**: FR-06, FR-11, FR-13

## UC-04. PR(1RM) 관리

- **액터**: 사용자
- **전제 조건**: 앱이 실행되어 있다.
- **트리거**: 사용자가 특정 종목의 신기록을 등록하려 한다.
- **기본 흐름**:
  1. 사용자가 종목, 중량, 단위, 날짜를 입력해 PR을 등록한다.
  2. 앱이 기존 PR과 비교해 갱신 여부를 판단하고, 갱신 이력을 보존한다.
  3. 사용자가 종목별 PR 목록과 갱신 이력을 조회한다.
- **예외 흐름**: 기존 PR보다 낮은 값을 입력하면 경고 후 사용자가 그래도 저장할지 선택한다.
- **사후 조건**: PR과 갱신 이력이 저장된다.
- **연관 기능 요구사항**: FR-07

## UC-05. 컨디션/부상 메모 기록

- **액터**: 사용자
- **전제 조건**: 세션 기록 화면에 진입해 있다.
- **트리거**: 사용자가 세션에 컨디션 메모를 추가한다.
- **기본 흐름**:
  1. 사용자가 통증 부위(선택)와 통증 강도(선택, 1~10) 및 자유 텍스트 메모를 입력한다.
  2. 사용자가 세션 저장 시 컨디션 메모가 함께 저장된다.
- **예외 흐름**: 통증 부위/강도 없이 텍스트 메모만 입력해도 저장을 허용한다.
- **사후 조건**: 컨디션 메모가 세션과 연결되어 저장된다.
- **연관 기능 요구사항**: FR-08

## UC-06. 운동 프로그램 템플릿 관리

- **액터**: 사용자
- **전제 조건**: 앱이 실행되어 있다.
- **트리거**: 사용자가 반복 사용할 운동 구성을 템플릿으로 저장하려 한다.
- **기본 흐름**:
  1. 사용자가 파트(포맷 포함)와 태그가 부여된 운동 블록 구성을 템플릿으로 저장한다.
  2. 사용자가 새 세션 기록 시 템플릿을 불러와 파트와 운동 블록을 자동으로 채운다.
  3. 사용자가 불러온 내용을 세션에 맞게 수정한 뒤 저장한다.
- **예외 흐름**: 템플릿을 삭제해도 이미 생성된 세션 기록에는 영향이 없다.
- **사후 조건**: 템플릿이 저장/수정/삭제되며, 세션 작성 시간이 단축된다.
- **연관 기능 요구사항**: FR-09

## UC-07. 사용자 정의 운동 종목 관리

- **액터**: 사용자
- **전제 조건**: 앱이 실행되어 있다.
- **트리거**: 사용자가 프리셋에 없는 운동 종목을 기록하려 한다.
- **기본 흐름**:
  1. 사용자가 종목 관리 화면 또는 블록 입력 중에 새 종목(이름, 카테고리(선택), 기본 무게 단위(선택))을 추가한다.
  2. 추가된 종목이 카탈로그에 저장되어 이후 블록 입력 시 선택 목록에 나타난다.
  3. 사용자가 기존 종목을 수정하거나 삭제할 수 있다.
- **예외 흐름**: 이미 기록에 사용된 종목을 삭제해도 과거 기록의 종목명은 그대로 유지된다.
- **사후 조건**: 사용자 정의 종목이 카탈로그에 저장되어 재사용 가능하다.
- **연관 기능 요구사항**: FR-11

## UC-08. 사용자 정의 태그 관리

- **액터**: 사용자
- **전제 조건**: 앱이 실행되어 있다.
- **트리거**: 사용자가 프리셋 태그(웜업/본운동/보조운동 등)로 충분히 구분되지 않는 블록을 표현하려 한다.
- **기본 흐름**:
  1. 사용자가 태그 관리 화면에서 새 태그(이름, 색상(선택))를 추가한다.
  2. 추가된 태그가 블록 입력 시 태그 선택 목록에 나타난다.
  3. 사용자가 기존 태그의 이름/색상을 수정하거나 삭제할 수 있다.
- **예외 흐름**: 이미 블록에 사용 중인 태그를 삭제하면 해당 블록에서 태그만 제거되고 블록은 유지된다.
- **사후 조건**: 사용자 정의 태그가 저장되어 블록 분류에 재사용 가능하다.
- **연관 기능 요구사항**: FR-12

## UC-09. 온보딩 및 업데이트 안내

- **액터**: 사용자
- **전제 조건**: 앱을 처음 실행했거나, 이전 버전에서 업데이트된 후 처음 실행한다.
- **트리거**: 앱이 최초 실행되거나, 업데이트 후 첫 실행된다.
- **기본 흐름**:
  1. 앱이 최초 실행 시 온보딩 화면(세션/히스토리/PR/관리 각 탭의 기능 소개)을 순서대로 보여준다.
  2. 사용자가 "다음"으로 다음 페이지로 넘기거나 "건너뛰기"로 즉시 종료할 수 있다.
  3. 온보딩을 마치거나 건너뛰면 이후 실행부터는 자동으로 표시되지 않는다.
  4. 사용자가 필요할 때(관리 탭) 온보딩을 수동으로 다시 볼 수 있다.
  5. 앱이 새 버전으로 업데이트된 후 첫 실행 시, 온보딩과 동일한 방식으로 해당 버전의 변경 사항을 안내한다.
- **예외 흐름**: 건너뛰기를 선택해도 이후 관리 탭에서 언제든 다시 열람할 수 있다.
- **사후 조건**: 온보딩/업데이트 안내를 확인했음이 저장되어 동일한 내용이 자동으로 반복 표시되지 않는다.
- **연관 기능 요구사항**: FR-14, FR-15

## UC-10. 버전 정보 조회

- **액터**: 사용자
- **전제 조건**: 앱이 실행되어 있다.
- **트리거**: 사용자가 관리 탭에서 "버전 정보"를 선택한다.
- **기본 흐름**:
  1. 사용자가 관리 탭의 "정보" 항목을 선택한다.
  2. 앱이 현재 버전(마케팅 버전, 빌드 번호)을 표시한다.
  3. 사용자가 필요 시 온보딩 다시 보기/업데이트 노트로 이동할 수 있다(선택).
- **예외 흐름**: 없음.
- **사후 조건**: 없음 (조회 전용).
- **연관 기능 요구사항**: FR-16

## UC-11. 데이터 내보내기/가져오기

- **액터**: 사용자
- **전제 조건**: 앱이 실행되어 있다.
- **트리거**: 사용자가 데이터를 백업하거나, 다른 기기 또는 재설치 후 복원하려 한다.
- **기본 흐름**:
  1. 사용자가 관리 탭에서 "데이터 내보내기"를 선택한다.
  2. 앱이 전체 데이터(세션/파트/블록/결과/종목/태그/PR/컨디션 메모/템플릿)를 파일로 내보내고, 시스템 공유 시트로 저장/전송할 수 있게 한다.
  3. 사용자가 다른 시점 또는 다른 기기에서 "데이터 가져오기"를 선택해 내보내기 파일을 선택한다.
  4. 앱이 파일 내용을 검증한 뒤 기존 데이터와 병합하거나, 사용자 확인을 받아 교체한다.
- **예외 흐름**:
  - 가져오기 파일 형식이 올바르지 않으면 오류를 안내하고 가져오기를 중단한다.
  - 가져오기 시 기존 데이터가 이미 있으면 병합할지 교체할지 사용자에게 확인한다.
- **사후 조건**: 내보내기 파일이 생성되거나, 가져온 데이터가 앱에 반영된다.
- **연관 기능 요구사항**: FR-17, FR-18
